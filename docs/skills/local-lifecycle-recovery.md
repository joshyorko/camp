# Local Lifecycle and Recovery

Issue #3 crash evidence uses the machine-readable schema at
`docs/evidence/crash-cut-ledger.schema.json` and the current ledger at
`docs/evidence/issue-3-crash-cut-ledger.json`. Each cut records its durable
precondition, injected death, recovery action, resulting journal state,
publication/cleanup result, and evidence artifacts. A cut is runtime-proven
only when its real gate runs against the exact `CAMP_TEST_BINARY`; unit tests
and skipped capability gates do not upgrade its status. The ledger candidate
records the exact commit and executable SHA-256, and runtime-proven entries
must contain evidence artifacts.

The current ledger intentionally marks the complete process-death matrix
blocked. `integration/forwarder_crash_test.go` implements the
forwarder-start-before-fact gate but does not provide current runtime proof.
The crash matrix also includes initial `ServiceStart` separately from
`ServiceRestart`. Required real capabilities must fail the gate explicitly;
the local crash gate does not require rsync, while remote mirror gates do.

## Current boundary

The production CLI exposes `init`, `open`, `sync`, `close`, `reopen`, `recover`, and an internal hidden `supervise` command owned by the Camp binary. Production read-write open must launch the hidden detached supervisor process, record the child claim as `ObservedPending`, compose heartbeat dependencies, then promote that exact supervisor record to `ObservedReady`; fail closed if the child identity never appears or if the child exits before readiness is recorded. Registry sealing models restart as a child intent authorized by the exact pending seal and preserves the newer service identity when the seal fact is composed from its older checkpoint snapshot.

The current multi-Camp candidate has not passed the complete real lifecycle.
Fresh-controller `reopen` discovers the current manifest and reads its durable
backend pointer; local journal history is optional selection convenience, not
portable generation authority. Keep fresh-controller file/MinIO reopen,
cross-controller OCI restore, the full crash matrix, unrelated-workspace
survival, and Kubernetes in `roadmap-gated` status until the exact candidate
passes their named executable gates.

Local workspace return is accepted only when the provider is marked local and the canonical staging root equals the canonical workspace-local folder. `internal/workspace/local.go` returns `MirrorLocalNoop`; it does not copy data. For a non-local provider, the checkpoint publisher accepts only `MirrorDevPodSSH`, builds from the returned nonempty staging root, and revalidates the writer lease after the mirror before recording the fact.

`app.NewCheckpointPublisher` accepts separate local and remote transports and always composes them through `workspace.NewSelector`. The selector uses the persisted `WorkspaceRecord.LocalProvider` value carried in `MirrorRequest`; it never probes or guesses locality. An open request that defaults the provider to Docker also persists `LocalProvider=true`, while an explicitly composed remote provider remains non-local. A missing matching transport fails closed. Every read-write open, including an adopted local root with no prior generation, acquires and journals a writer lease before workspace effects; its `OpenedGeneration` remains nil. This is required because sync and close reject publication without the exact active lease revision.

## Recovery rules

- Machine config is defaults-only. A camp root owns a private, versioned `.camp/camp.yaml` with `schemaVersion: 1`, stable `id`, `source: .`, explicit backend, and explicit workspace provider/context. Discovery walks canonical parents read-only and fails closed on symlinks, duplicate or unknown YAML fields, unsupported versions, path escape, credentials, and conflicting initialization.
- Legacy singleton config containing `defaultCapsule` plus `source` is migrated automatically on first directory-based camp resolution only when the canonical source contains regular, matching schema-v1 capsule metadata and manifest/backup publication is conflict-free. Migration preserves the original as `config.yaml.bak`, creates or validates the manifest, then atomically rewrites machine defaults without camp selection. Missing or mismatched capsule metadata, a conflicting manifest, or a different existing backup fails without rewriting config and returns `camp init --migrate` as the actionable recovery. Explicit session/camp selection remains higher precedence and does not mutate unrelated legacy config. Rerunning after a completed migration is idempotent.
- `camp reopen [session]` uses history only as selection convenience: an explicit session remains journal-authoritative and fails closed when absent; otherwise Camp selects the current camp's newest closed record when available, or follows `open` from the current manifest to read the backend pointer on a fresh controller. The manifest/backend pointer, not a portable journal, is generation authority. `camp status --camp …` or `--session …` reports the selected record and emits `camp recover --session …` only when recovery is actually required.
- The operator surface also includes `camp list` and `camp strike`. `camp list` derives stored camps from validated latest-pointer objects plus journal history and sorts the merged inventory deterministically by capsule and branch.
- Human `sync` and `close` output streams typed milestones only after each durable effect completes; JSON mode remains one non-streamed success envelope. Progress is stage-based and never fabricates percentages.
- Rich human checkpoint rendering may begin at an explicit ordered suffix when durable recovery has already established earlier checkpoint or cleanup stages; omitted prefix stages are neither displayed nor marked complete. Read-only sync and already-closed or already-published results use result-backed no-stage text. A pending or failed serving refresh cannot produce the rich success band, while plain and JSON result formats retain their established contracts.
- `camp strike` is the recoverable local reset and remains usable when a stale writer lease blocks ordinary close/recovery. Before archiving, it quiesces every active journal by deleting the exact recorded DevPod workspace, stopping identity-verified forwarders and services, and stopping the recorded supervisor when present; incomplete abandoned opening records with no effects are skipped. A recoverable strike leaves materializations in the archived controller tree even when their ownership marker no longer matches. Permanent `camp strike --purge --yes` still requires ownership-verified removal of every Camp-created materialization and fails closed on mismatch. Strike does not require or release the stale writer lease because the managed backend containing that lease is itself part of the reset. It still refuses S3 or an external file backend. With Camp's managed file backend it archives verified controller-owned data-root children to a timestamped sibling while preserving machine configuration and managed `tools`; source roots and their manifests are outside the controller reset. `--purge` without `--yes` is rejected. Targets must be real direct-child directories and are revalidated immediately before rename or removal, so symlinks and path substitution fail closed.

- Treat a pending journal intent as reconciliation work, not permission to repeat a side effect.
- A pending `WorkspaceMirrored` intent blocks another checkpoint because its side-effect outcome is unknown. An ambiguous mirror fact does not block a later checkpoint: preserve its returned attempt ID/root as evidence, then allocate the next logical attempt and a fresh attempt-specific staging destination. Do not stop/delete the provider workspace or remove controller staging when mirroring or pointer CAS fails.
- `WorkspaceRecord.mirror` is a required value object in serialized snapshots; an empty `{}` truthfully means no mirror attempt has been recorded. Completed and ambiguous facts carry the durable logical-attempt number used to allocate the next unique checkpoint attempt after restart.
- Validate that the persisted workspace type has a matching composed transport before recording `WorkspaceMirrored`. For remote transports, validate the persisted workspace ID and DevPod context against the composed transport at the same pre-intent boundary. Missing composition or identity mismatch is an effect-free configuration error and must not create false pending reconciliation work.
- Remote close order is final publication, provider stop/delete, forwarders/services/supervisor, private session-runtime removal, conditional lease release, then owned staging/materialization cleanup. Forwarders stop through `ForwarderManager.Stop`, including the already-absent process case, so the evidence pathname is removed only when its recorded device/inode still matches. Runtime removal accepts only the recorded service logs, derived forwarder logs, and the exact session ownership seed as private single-link regular files; an unexpected entry, symlink, hard link, mismatched seed, or path-layout mismatch preserves the runtime root and fails cleanup. Camp removes its empty per-session and `camp` runtime directories, but the containing `XDG_RUNTIME_DIR` remains caller-owned. `--keep-workspace` changes the provider action but does not make controller staging user-owned.
- If cleanup is already running or failed and the journal contains exactly one pending close cleanup intent, close resumes that exact recorded intent without republishing the checkpoint. Supported pending cleanup transitions in this slice are `WorkspaceStoppedOrDeleted`, `ForwardersStopped`, `ServicesStopped`, `SupervisorStopped`, and `SessionArtifactsRemoved`; `LeaseReleased` and the materialization transitions still fail closed.
- Any non-empty pending close cleanup intent set must fail closed unless cleanup is already `running` or `failed`; otherwise close must not ignore the pending work.

- A Kubernetes DevPod provider does not necessarily install an OpenSSH `<workspace>.devpod` alias. Production remote mirroring therefore uses `devpod ssh --context <context> --start-services=false --command <tar>` as the tar producer and a fresh Camp-owned attempt directory as the local consumer. The consumer argv is restricted to the GNU/BusyBox-compatible `--extract`, `--file=-`, `--directory=<root>`, and `-p` subset; `-p` prevents an ordinary user's umask from silently changing restored modes while archive headers preserve hard links, symlinks, and bytes. Avoid GNU-only long options that make BusyBox exit early and break the producer pipe. An rsync attempt that depends on a missing SSH alias fails after starting and is outcome-ambiguous; do not use that failed attempt as a routine fallback trigger.
- `WorkspaceRecord.LocalProvider` never suppresses close-time DevPod teardown. `CloseWorkspace` still requires the recorded workspace ID and context, then stops or deletes the exact recorded workspace according to `--keep-workspace` and `Recovery.Cleanup.WorkspaceAction`; local-provider mirroring only changes the transport selection, not the lifecycle contract.
- Do not clean up adopted content. Camp-created materializations require matching canonical path, ownership marker, device, and inode evidence.
- Accept a real source directory reached through a symlinked ancestor, including Bluefin's `/home/<user>` to `/var/home/<user>` mapping. Reject a source whose final path component is itself a symlink, retain the original path for recovery evidence, and use the resolved canonical directory for lifecycle and ownership checks.
- A failed sync before durable checkpoint recovery state exists must be retried with `camp sync --session <session-id>`. A failed close before checkpoint publication must be retried with `camp close --session <session-id>`; `camp recover <session-id>` is reserved for a published checkpoint whose remaining close cleanup is recoverable. Do not suggest recovery merely because sync or close began.
- Ambiguous and definitive `WorkspaceUp` failures may include a bounded DevPod diagnostic. Camp bounds raw output before sanitizing, redacts unlabeled secret-like lines and bare credential-shaped values, escapes terminal controls and bidi/format runes, and enforces a final rendered 8 KiB cap before returning the error. After a transient `Busy` wait reaches `Running`, reconciliation must list the exact workspace again and revalidate context, provider, and source folder before recording the fact.
- Crash-matrix evidence is collected under a dedicated bounded diagnostic context and then followed by a fresh mandatory-cleanup context; do not reuse the diagnostic context for teardown. The `TestLocalLifecycleCrashMatrix` retry gate retries only when cleanup completes without error and the test emits the exact post-cleanup receipt `{"retry":"crash-matrix-bootstrap"}`; assertion or cleanup failures suppress that receipt and must not be rerun.
- Ownership-marker tests that exercise the named temporary-file substitution path must inject `createNamedOwnershipMarkerTemporary`. Linux filesystems may allow the production `O_TMPFILE` path and therefore produce no temporary filename.
- Service status must call `ServiceSupervisor.Observe`; journaled `ready` state is not live evidence. Observation reconstructs the exact recorded Pasta/Hauler command, inspects the recorded helper and child identities, and reruns listener/readiness checks. PID reuse and listeners remaining after a stopped helper fail closed. The stopped check is read-only; PID-file removal remains exclusive to the explicit absence/cleanup path.
- Forwarder recovery carries a durable `EvidencePath` plus the published file's device/inode identity in `ForwardingRecord`. `ForwarderManager.Start` rejects pre-existing evidence, validates the launched process against the canonical executable and complete generated DevPod command, and publishes the private `0600` JSON record with fsync plus an atomic no-replace rename before readiness polling completes. Recovery opens that one-link, owner-matching, size-bounded record once with `O_NOFOLLOW`, validates the same inode before and after decoding, reconstructs the complete DevPod argv and digest, and facts the pending start without launching a duplicate. PID, boot ID, start ticks, process group, session, namespace, executable, and argv are stable evidence; PPID is informational because a surviving forwarder is reparented after the controller dies. Missing, changed, or mismatched evidence fails closed. Cleanup first quarantines the pathname and removes it only when it still names the recorded device/inode, so a replacement file is restored rather than deleted.
- Service restart records `ServiceRestart` before stopping anything, stops through the identity-checked child-first supervisor path, and reuses only the recorded command and endpoint contract with a new launch token. When observation already proves the unit stopped, restart runs the explicit `Absent` cleanup path before start so a stale private PID file cannot block recovery. Application restart holds the session operation lock and runs the ownership/session/lease safety guard before calling the supervisor.
- If registry stop reports an error before the cut callback, re-observe the exact recorded unit. When it is durably stopped, restart it under the pending seal with the same launch token because no cut ran; if a later retry finds that same stopped pre-cut state, repair it only when the final snapshot path is absent and require another retry before sealing. A present snapshot with a stopped registry is outcome-ambiguous and fails closed.
- A failed pre-cut repair can leave exactly the seal intent plus its deterministic same-token `ServiceRestart` child intent. Reconcile only that exact pair under the seal parent, then require a fresh retry; unrelated pending work remains blocking.
- `RegistrySnapshotSealed` composition preserves current service identities, so callback-driven nested restart updates to helper and child identities are durable through registry-seal replay and are not overwritten by stale checkpoint snapshot state.
- Service logs are addressed by a journal-owned service name, never a caller path. `ServiceLogReader` accepts only a regular, private, single-link file below its configured canonical log root, rejects symlinks and path escape, and returns at most the configured tail bound.
- Keep durable journals, generations, and ownership evidence under `XDG_DATA_HOME`, but place Pasta-owned log and PID files below Camp's `XDG_RUNTIME_DIR` root. On SELinux-enforcing Bluefin, Pasta cannot create those ephemeral files beneath a `data_home_t` session directory; the per-user runtime directory provides the correct transient boundary and is recreated safely after login or reboot. When `XDG_RUNTIME_DIR` is unavailable, Camp retains the data-root fallback for compatibility rather than inventing an unauthenticated global runtime path.
- Process-group cleanup reads `/proc/<pid>/stat` first and fully inspects only processes whose PGID matches the recorded group. An unrelated kernel worker with inaccessible executable identity must not block cleanup, while a matching candidate that changes identity or PGID during full inspection fails closed. During post-stop verification, a helper can exit between stat qualification and cmdline/executable inspection; Camp polls that same PID/start/PGID for at most 250 ms and accepts only a successful exact inspection, disappearance, or zombie state. Stable inspection failure and any identity/group drift still fail closed. `Stop` likewise does not treat a transient full-inspection failure as disappearance while stat still reports the same live PID/start identity. A detached Pasta helper may be reparented after the launching Camp command exits. If the kernel later denies its `/proc/<pid>/exe` or network-namespace link, helper validation accepts only ProcessManager's resolved exact `argv[0]` executable and `kernel-denied:<boot-id>:<start-ticks>` namespace evidence; arbitrary replacement paths or namespace values still fail closed. Its PID/boot/start identity, exact argv and digest, PGID, and SID remain mandatory. The recorded Hauler child must still retain its exact parent, executable path, and network namespace in addition to those checks.
- Image list output is derived from the selected session's persisted inventory and carries the session, capsule, branch, and checkpoint-base generation/digest; image and tag arrays are sorted before presentation.
- Hauler v2.0.2 has no general command that scans a local Docker or Podman engine and generates a manifest. `hauler store sync --products <name=version> --dry-run` only prints a curated product collection fetched from a product registry, while `hauler store add chart <chart> --add-images` discovers image references from that chart. Upstream's cluster-image recipe uses `kubectl` plus shell formatting to create `hauler-manifest.yaml`, then runs `hauler store sync --filename hauler-manifest.yaml`. Camp deliberately does not add engine discovery: only an explicit push through `CAMP_REGISTRY` enters the immutable registry cut and checkpoint inventory.
- `camp images capture` fails before lifecycle dispatch with stable guidance to push through `CAMP_REGISTRY` and run `camp sync` or `camp close`; it does not acquire the session lock, write an empty inventory, or expose the obsolete `--exclude-tag` engine-discovery option. Image restore still holds the session operation lock, rejects unrelated pending work, revalidates ownership/session/lease state, proves the recorded registry service live, and accepts only the selected session inventory. Restore retains digest verification and never accepts caller-supplied lineage.
- Legacy `ImagesCaptured` recovery remains no-engine-discovery behavior for already-persisted intents, but no public command creates new capture intents. Restore remains digest-verified, idempotent for already-correct original tags, and replayable through `WorkspaceImagesRestored` against the committed registry authority and endpoint from the checkpoint snapshot.
- A sync retry may resume one exact checkpoint intent only from its durable stage evidence. Checkpoint intent IDs use the logical `<session>-checkpoint-<n>` attempt; a remote mirror may persist the related transport attempt with a `-rsync` or `-tar` suffix, which must validate against but never replace the logical ID during reconciliation. `WorkspaceImagesInventoried` records the no-engine-discovery capture boundary without repeating the workspace mirror; `RegistrySnapshotSealed` then derives the transported inventory exclusively from the exact immutable cut. `RootSnapshotStable` rebuilds only when the logical attempt ID, completed mirror transport/root, generation, and sealed registry-cut path match. `GenerationUploaded` re-verifies the exact local haul and immutable remote generation without rebuilding, recapturing, resealing, or remirroring. `PointerCommitted` first re-reads the verified immutable generation metadata; the complete pending pointer must be derived from that metadata before an already committed exact pointer can be adopted or the original compare-and-swap baseline can govern the retry. The pointer fact advances the durable baseline before any serving refresh or close cleanup. Any request, identity, generation, path, digest, size, timestamp, tools, parent, session, or registry-cut drift fails closed.
- The simulated checkpoint crash matrix fails each stage's first fact append after its effect. Retry repeats only the unfinished stage for image inventory, registry seal, root archive construction, immutable upload verification, pointer adoption, and serving refresh; its call-count assertions prove that earlier stages are not replayed. An unfacted workspace transfer remains pending and refuses a second transfer because no observation contract can distinguish its outcome.
- After `PointerCommitted`, retry an exact pending `ServingContentRefreshed` intent only from the published checkpoint and its deterministic nested `ServiceStart` children. `sync` and `close` delegate to that refresh-only reconciliation without repeating mirror, capture, seal, upload, or pointer publication; `close` begins cleanup only after the pending refresh is facted. Refreshed Hauler services preserve the child context prefix reconstructed from the durable helper argv. A legacy pending start that omitted that prefix may be retried only when every other start field matches and the durable record proves the exact prefix.
- Service shutdown polls the post-stop `Absent` proof for at most one second so kernel listener teardown can settle; unknown errors and any invariant that remains at the deadline still fail closed. An expired or replaced writer lease blocks publication and cleanup, retaining the workspace rather than acting as a losing writer. A replacement supervisor may immediately renew an expired lease only when the backend still contains the exact recorded lease document and revision; the conditional write loses safely if another writer already replaced it. Production supervisors retain the same 30-minute TTL used by open, renew every one-third TTL, and treat operation-lock contention from sync or close as a missed heartbeat rather than a fatal supervisor error. Other renewal, ownership, journal, or lock failures remain fatal.
- Production read-write open is not complete until the hidden supervisor child has been started by the Camp binary and the journal shows the exact recorded process identity. Claiming first requires the named session to remain opening, open, or recovering; closed and otherwise inactive journals reject the hidden command before any claim intent or fact. A `SupervisorClaimed` intent carries that identity and the requested pending/ready state, so a fact-write cut is reconciled as journal-only work before a replacement claimant records its own intent; malformed, identity-incomplete, or unrelated pending work fails closed. An empty-input legacy claim is facted without inventing identity state so a replacement can claim normally. Re-entry reuses a ready owner only when there is no pending recovery and exact live-process inspection matches; an exact live pending owner is in flight and must be awaited, while PID reuse starts a replacement without signaling the unrelated process. Each heartbeat re-acquires the session operation lock, reloads durable state, compares the journaled PID/boot/start identity with its own current identity before lease effects, and exits on replacement. Cancellation releases the lock cleanly. `StopSupervisor` still rejects an incomplete identity and close must not weaken that guard.

Immediately before assembly, Camp reopens each canonical directory with `openat2` no-symlink/no-cross-device constraints and requires its device/inode identity to match the held descriptor; replacement fails before Hauler runs.
- The normal operator cycle is `exit` from an attached shell, `camp close` on the host, `camp reopen`, then `camp attach`. Treating the committed pointer as absent also makes writer-lease acquisition correctly fail with `pointer appeared after absent observation`.

Retry only while the original revision and bytes remain; adopt a different revision only after exact replacement readback succeeds. Validate repository/tag/digest syntax and fail closed on malformed or conflicting links.

Apply this exclusion after deriving the inventory from the cut, because that is where a loaded generation's file projection first enters the candidate inventory.

The encoder inserts the inter-document `---` marker; adding another marker creates an empty document that the generation assembler correctly rejects as an unsupported manifest kind. Keep that rejection strict and fix separators at the producer.
