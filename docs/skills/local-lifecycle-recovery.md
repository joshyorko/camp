# Local Lifecycle and Recovery

## Current boundary

The production CLI exposes `init`, `open`, `sync`, `close`, `reopen`, `recover`, and an internal hidden `supervise` command owned by the Camp binary. A fresh-XDG real-tool smoke has proved `init` and `open` through DevPod and Hauler, including in-workspace access to the forwarded registry and fileserver. Production read-write open must also launch the hidden detached supervisor process, wait until the child journals a complete exact `SupervisorRecord`, and fail closed if that supervisor identity never appears; a zero-value supervisor at open return is a bug, not an accepted state. Real image capture also reached a working nested Docker engine and captured a named image, but the same run exposed restart ordering beneath a pending `RegistrySnapshotSealed` intent after the registry was stopped. Recovery now models that restart as a child intent authorized by the exact pending seal and preserves the newer service identity when the seal fact is composed from its older checkpoint snapshot. The complete `sync → close → fresh-controller reopen` acceptance remains required before describing the local vertical as usable; do not treat focused recovery tests or image capture alone as checkpoint or recovery proof.

Local workspace return is accepted only when the provider is marked local and the canonical staging root equals the canonical workspace-local folder. `internal/workspace/local.go` returns `MirrorLocalNoop`; it does not copy data. For a non-local provider, the checkpoint publisher accepts only `MirrorDevPodSSH`, builds from the returned nonempty staging root, and revalidates the writer lease after the mirror before recording the fact.

`app.NewCheckpointPublisher` accepts separate local and remote transports and always composes them through `workspace.NewSelector`. The selector uses the persisted `WorkspaceRecord.LocalProvider` value carried in `MirrorRequest`; it never probes or guesses locality. An open request that defaults the provider to Docker also persists `LocalProvider=true`, while an explicitly composed remote provider remains non-local. A missing matching transport fails closed. Every read-write open, including an adopted local root with no prior generation, acquires and journals a writer lease before workspace effects; its `OpenedGeneration` remains nil. This is required because sync and close reject publication without the exact active lease revision.

## Recovery rules

- Treat a pending journal intent as reconciliation work, not permission to repeat a side effect.
- A pending `WorkspaceMirrored` intent blocks another checkpoint because its side-effect outcome is unknown. An ambiguous mirror fact does not block a later checkpoint: preserve its returned attempt ID/root as evidence, then allocate the next logical attempt and a fresh attempt-specific staging destination. Do not stop/delete the provider workspace or remove controller staging when mirroring or pointer CAS fails.
- `WorkspaceRecord.mirror` is a required value object in serialized snapshots; an empty `{}` truthfully means no mirror attempt has been recorded. Completed and ambiguous facts carry the durable logical-attempt number used to allocate the next unique checkpoint attempt after restart.
- Validate that the persisted workspace type has a matching composed transport before recording `WorkspaceMirrored`. For remote transports, validate the persisted workspace ID and DevPod context against the composed transport at the same pre-intent boundary. Missing composition or identity mismatch is an effect-free configuration error and must not create false pending reconciliation work.
- Remote close order is final publication, provider stop/delete, forwarders/services/supervisor, conditional lease release, then owned staging/materialization cleanup. `--keep-workspace` changes the provider action but does not make controller staging user-owned.
- If cleanup is already running or failed and the journal contains exactly one pending close cleanup intent, close resumes that exact recorded intent without republishing the checkpoint. Supported pending cleanup transitions in this slice are `WorkspaceStoppedOrDeleted`, `ForwardersStopped`, `ServicesStopped`, and `SupervisorStopped`; `LeaseReleased` and the materialization transitions still fail closed.
- Any non-empty pending close cleanup intent set must fail closed unless cleanup is already `running` or `failed`; otherwise close must not ignore the pending work.
- Run the production local vertical with `CAMP_TEST_REAL_LIFECYCLE=1 go test -v ./integration -run '^TestLocalLifecycleVertical$' -count=1 -timeout=60m`. With the gate enabled, missing DevPod, Hauler, Pasta, Docker CLI, or workspace image-engine capability is a failure rather than a skip. The gate keeps one DevPod workspace, exercises direct `CAMP_REGISTRY` and fileserver access, and owns teardown. As of the current issue #3 branch, it deliberately remains red because the Room workspace exposes no usable Docker, Podman, or nerdctl engine after open; do not represent local named-image lifecycle as generally ready until this passes.
- `WorkspaceRecord.LocalProvider` never suppresses close-time DevPod teardown. `CloseWorkspace` still requires the recorded workspace ID and context, then stops or deletes the exact recorded workspace according to `--keep-workspace` and `Recovery.Cleanup.WorkspaceAction`; local-provider mirroring only changes the transport selection, not the lifecycle contract.
- Do not clean up adopted content. Camp-created materializations require matching canonical path, ownership marker, device, and inode evidence.
- After a successful checkpoint build, the application and public CLI recovery command is `camp recover <session-id>`.
- Ownership-marker tests that exercise the named temporary-file substitution path must inject `createNamedOwnershipMarkerTemporary`. Linux filesystems may allow the production `O_TMPFILE` path and therefore produce no temporary filename.
- Service status must call `ServiceSupervisor.Observe`; journaled `ready` state is not live evidence. Observation reconstructs the exact recorded Pasta/Hauler command, inspects the recorded helper and child identities, and reruns listener/readiness checks. PID reuse and listeners remaining after a stopped helper fail closed. The stopped check is read-only; PID-file removal remains exclusive to the explicit absence/cleanup path.
- Service restart records `ServiceRestart` before stopping anything, stops through the identity-checked child-first supervisor path, and reuses only the recorded command and endpoint contract with a new launch token. When observation already proves the unit stopped, restart runs the explicit `Absent` cleanup path before start so a stale private PID file cannot block recovery. Application restart holds the session operation lock and runs the ownership/session/lease safety guard before calling the supervisor.
- If registry stop reports an error before the cut callback, re-observe the exact recorded unit. When it is durably stopped, restart it under the pending seal with the same launch token because no cut ran; if a later retry finds that same stopped pre-cut state, repair it only when the final snapshot path is absent and require another retry before sealing. A present snapshot with a stopped registry is outcome-ambiguous and fails closed.
- A failed pre-cut repair can leave exactly the seal intent plus its deterministic same-token `ServiceRestart` child intent. Reconcile only that exact pair under the seal parent, then require a fresh retry; unrelated pending work remains blocking.
- `RegistrySnapshotSealed` composition preserves current service identities, so callback-driven nested restart updates to helper and child identities are durable through registry-seal replay and are not overwritten by stale checkpoint snapshot state.
- Service logs are addressed by a journal-owned service name, never a caller path. `ServiceLogReader` accepts only a regular, private, single-link file below its configured canonical log root, rejects symlinks and path escape, and returns at most the configured tail bound.
- Process-group cleanup reads `/proc/<pid>/stat` first and fully inspects only processes whose PGID matches the recorded group. An unrelated kernel worker with inaccessible executable identity must not block cleanup, while a matching candidate that changes identity or PGID during full inspection fails closed. During post-stop verification, a helper can exit between stat qualification and cmdline/executable inspection; Camp polls that same PID/start/PGID for at most 250 ms and accepts only a successful exact inspection, disappearance, or zombie state. Stable inspection failure and any identity/group drift still fail closed. `Stop` likewise does not treat a transient full-inspection failure as disappearance while stat still reports the same live PID/start identity. A detached Pasta helper may be reparented after the launching Camp command exits, so helper validation does not treat `ParentPID` as stable; the recorded child must still retain its exact parent and all helper and child PID/start-time, executable, argv digest, PGID, SID, and namespace checks remain mandatory.
- Image list output is derived from the selected session's persisted inventory and carries the session, capsule, branch, and checkpoint-base generation/digest; image and tag arrays are sorted before presentation.
- Image capture and restore hold the session operation lock, reject unrelated pending work, revalidate ownership/session/lease state, and prove the recorded registry service live immediately before engine or registry effects. If the selected session identity changes after lock acquisition, the operation releases the lock and returns the canonical `ErrRecoveryIdentityChanged` before guard, engine, or registry effects. Capture persists only a schema-valid inventory whose entries have captured references and verified manifest digests. Restore accepts only that selected session inventory, never caller-supplied lineage.
- A retry may reconcile one exact pending `ImagesCaptured` intent. If the deterministic captured reference already exists without a journal fact, capture adopts it only when the current workspace engine proves the same local image ID exposes the registry's resolved repository digest; otherwise it remains a collision and fails closed. Restore is digest-verified and idempotent for already-correct original tags.
- A sync retry may resume one exact pending `RootSnapshotStable` intent only when its attempt ID, completed mirror root, generation, and sealed registry-cut path match durable session state. It rebuilds the local verified archive for that intent without repeating workspace mirroring, image capture, or registry sealing; any identity or path drift fails closed.
- After `PointerCommitted`, retry an exact pending `ServingContentRefreshed` intent only from the published checkpoint and its deterministic nested `ServiceStart` children. `sync` and `close` delegate to that refresh-only reconciliation without repeating mirror, capture, seal, upload, or pointer publication; `close` begins cleanup only after the pending refresh is facted. Refreshed Hauler services preserve the child context prefix reconstructed from the durable helper argv. A legacy pending start that omitted that prefix may be retried only when every other start field matches and the durable record proves the exact prefix.
- Service shutdown polls the post-stop `Absent` proof for at most one second so kernel listener teardown can settle; unknown errors and any invariant that remains at the deadline still fail closed. An expired or replaced writer lease blocks publication and cleanup, retaining the workspace for explicit operator recovery rather than acting as a losing writer.
- Production read-write open is not complete until the hidden supervisor child has been started by the Camp binary and the journal shows the exact recorded process identity; each heartbeat re-acquires the same session operation lock, reloads durable state under that lock, and cancellation releases the lock cleanly. `StopSupervisor` still rejects an incomplete identity and close must not weaken that guard.
- Derive direct-push repository, tag, and digest references from regular `current/link` files inside the immutable registry cut while the write barrier is held. Hauler v2.0.2 rejects paginated `_catalog` requests and its unpaginated catalog can omit repositories that are present in the distribution storage tree; the live catalog is therefore not complete-enough publication evidence. Validate repository/tag/digest syntax and fail closed on malformed or conflicting links.
- Exclude Camp's internal `hauler/camp-session-seed:latest` file artifact from image inventory and Hauler image-digest validation. It exists to initialize the Hauler store and is not a user OCI image; direct user pushes remain inventoried from the immutable cut.
- Generate the Hauler `Files` and `Images` documents with one YAML encoder. The encoder inserts the inter-document `---` marker; adding another marker creates an empty document that the generation assembler correctly rejects as an unsupported manifest kind. Keep that rejection strict and fix separators at the producer.
