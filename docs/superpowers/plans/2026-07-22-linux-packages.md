# Linux Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce reproducible amd64/arm64 generic archives, DEB, RPM, APK, and locally testable Homebrew artifacts with clean install, first-use bootstrap, upgrade, and uninstall evidence.

**Architecture:** Extend the existing normalized archive build into one release builder that stages the same binary, documentation, and generated completions for every format. Use a pinned nfpm release for native Linux package encoding, format-specific dependency metadata for the `passt` project and `pasta` executable, and container fixtures for clean package-manager acceptance. Render a real formula into an isolated local tap and test Homebrew's install and upgrade mechanism against local artifacts.

**Tech Stack:** Go, Bash, nfpm, Podman/Docker-compatible Linux containers, Homebrew, Go test.

## Global Constraints

- Build from current `origin/master` on `patchraptor/issue-12-linux-packages`.
- Support Linux amd64 and arm64 artifacts.
- Every artifact carries the same version, commit, UTC build date derived from `SOURCE_DATE_EPOCH`, and clean dirty state.
- Package construction is byte reproducible across isolated builds; any unavoidable container/package-manager state is outside the artifact comparison.
- DEB/RPM/APK package metadata declares the distro package that provides `pasta`; generic archives and Homebrew declare the external prerequisite truthfully.
- Installed completions are generated by the packaged command tree.
- Acceptance never silently skips packaged CLI, clean install, first-use managed-tool bootstrap, upgrade, or uninstall checks.
- Runtime DevPod/MinIO lifecycle acceptance remains serialized and owned by the root lane.
- No release publication, host package layering, credentials, or deployment.
