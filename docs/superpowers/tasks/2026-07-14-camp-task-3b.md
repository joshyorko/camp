## Required outcome

Implement the smallest complete open/re-entry application slice that can:

1. Resolve strict disjoint XDG paths and a strict `file://` backend using the existing config records.
2. Create or resume one durable session using the existing atomic session store and zero/one/many selector.
3. Resolve exactly one source:
   - adopt an explicit/configured local Second Brain root without ever making it Camp-deletable; or
   - observe/revalidate a pointer, acquire the correct main/branch lease, fetch and verify the immutable generation, load it with real Hauler, securely extract it, and create a Camp-owned materialization.
4. Make remote hydration and ownership one recoverable controller. Journal a random ownership/materialization token before extraction. Stage under a session-owned path. Commit by atomic rename. Record the final canonical path, marker/token, device, inode, generation identity, and ownership mode only after observing them. Recovery must safely handle every cut before extraction, after stage creation, after extraction, after final rename, and before/after ownership fact.
5. Preserve any adopted root permanently. Reject and preserve unexplained, pre-existing, symlinked, marker-mismatched, device/inode-mismatched, or out-of-XDG destinations. Never merge, overwrite, or recursively delete them.
6. Apply the stable capsule documents/devcontainer fallback through existing `capsule.Initializer`, then resolve the requested target only after the final root is committed/adopted.
7. Build the deterministic workspace ID and typed `CAMP_REGISTRY`, `CAMP_FILESERVER`, `CAMP_CAPSULE`, and opened-value `CAMP_CHECKPOINT` inputs for DevPod. Reconcile `devpod up` once, query the effective workspace root, map the target, and dispatch terminal entry through the typed DevPod SSH/shell abstraction. The re-entry path must select an existing opening/open/recovering session and must not hydrate, lease, or create a second workspace again.
8. Persist enough intent/fact/recovery state that a new process can continue safely without persisting credentials or raw bootstrap config.

If an existing interface cannot express a required invariant, extend it additively. Keep `CheckpointPublisher` the only publication path. Do not duplicate coordination policy or bypass existing archive, Hauler, journal, ownership, target, workspace, or DevPod adapters.

## Required tests

Add focused tests before production changes for:

- adopted root open records non-deletable ownership and survives all recovery cuts;
- remote generation hydrate records token before stage, uses a session-owned stage, atomically commits, and produces a removable created ownership record only after identity validation;
- crashes at stage-created, extract-complete, rename-complete, and ownership-fact boundaries converge without overwrite, duplicate extraction, or adopted-root deletion;
- unexplained final/stage paths, symlinks, marker mismatch, device/inode mismatch, and outside-XDG targets fail closed;

- typed DevPod environment uses the opened checkpoint, exact `--context default --provider docker --ide none --open-ide=false` when supplied, and shell fallback remains executable when host tmux is absent;
- durable records and haul/session artifacts contain no configured credentials.

At minimum, cover new code in `internal/app`, `internal/capsule`, and any new hydration adapter/controller. Reuse real filesystem behavior in tests; use narrow recording fakes only at external process/object-store boundaries.
